# プロダクト要求定義書（PRD）

## 1. プロダクト概要

### 1.1 プロダクト名（仮）
**ParkFinder**（周辺駐車場検索ツール）

### 1.2 ビジョン
車での外出時に「目的地の近くにどんな駐車場があるか」を、出発前・到着直前のどちらでもスマホからすぐに把握できるようにする。

### 1.3 目的
- 地図上でクリック（タップ）した地点の周辺にある駐車場を、一覧と地図で素早く確認できる
- 無料で運用できる構成とし、個人利用で継続的に使える
- 将来、地図・データ提供元（OpenStreetMap ⇔ Google Maps）を切り替えられる設計とする

### 1.4 スコープ外（現バージョン）
- 駐車場の空き（満空）情報
- 駐車場の料金情報
- ユーザー登録・ログイン、複数端末間のデータ同期
- 一般公開・収益化

## 2. ターゲットユーザー

### 2.1 ペルソナ
| 項目 | 内容 |
|---|---|
| 利用者 | 開発者本人（個人利用） |
| 移動手段 | 自家用車 |
| 行動範囲 | 自身の生活圏＋隣県 |
| 利用端末 | 主にスマートフォン（出発前は PC を使う場合もある） |

### 2.2 課題・ニーズ
- 行き慣れない目的地だと、近くに駐車場があるか分からず不安
- 到着直前に運転の合間で駐車場を探すのは手間がかかる
- 汎用の地図アプリでは「目的地から◯m以内の駐車場を距離順に見る」といった使い方がしにくい

## 3. 利用シーン

1. **出発前**：自宅で目的地付近を地図上でタップし、周辺の駐車場の候補を確認する
2. **到着直前**：同乗者または停車中に、現在地や目的地周辺の駐車場を確認し、ナビアプリで向かう

## 5. ユーザーストーリー

- **US-01**：利用者として、地図上の目的地をタップしたい。周辺の駐車場を一度に把握するためだ。
- **US-02**：利用者として、駐車場を近い順に一覧で見たい。どこに停めるかを素早く決めるためだ。
- **US-03**：利用者として、検索範囲を変更したい。候補が少ないときに範囲を広げるためだ。
- **US-04**：利用者として、現在地の周辺をワンタップで検索したい。到着直前に手間なく探すためだ。
- **US-05**：利用者として、選んだ駐車場へナビを開始したい。そのまま向かうためだ。
- **US-06**：利用者として、地名で場所を探したい。地図を手で動かさずに目的地付近を表示するためだ。
- **US-07**：利用者として、良かった駐車場を保存してメモを残したい。次回また使うためだ。

## 6. 受け入れ条件

| ストーリー | 受け入れ条件 |
|---|---|
| US-01 | 地図をタップすると中心マーカーが表示され、指定半径内の駐車場がマーカーで表示される |
| US-01 | 該当する駐車場が 0 件の場合、「見つかりませんでした」と半径拡大の案内を表示する |
| US-02 | 一覧が中心地点からの直線距離の昇順で並び、各項目に距離（m）が表示される |
| US-02 | 一覧の項目を選ぶと、地図上の該当マーカーが強調表示される（逆方向の操作も同様） |
| US-03 | 半径を変更すると、同じ中心地点で再検索される |
| US-04 | 位置情報の許可後、現在地を中心に検索される。拒否された場合は案内メッセージを表示する |
| US-05 | 「ナビ」ボタンで外部地図アプリが開き、目的地に駐車場の座標が設定されている |
| US-06 | 地名を入力して候補を選ぶと、地図がその地点へ移動する |
| US-07 | お気に入りとメモがブラウザを再読み込みしても保持される |
| 共通 | データ取得に失敗した場合、エラーメッセージと再試行の手段を表示する |

## 7. 機能要件

### 7.1 地図・検索
- 地図の初期表示位置は、前回表示していた位置とする（初回はあらかじめ決めた既定の位置）
- 検索半径の初期値は 500m とする
- 駐車場データは OpenStreetMap（Overpass API）から取得する
  - 対象：`amenity=parking`（必要に応じて `amenity=motorcycle_parking` 等は除外）
  - 取得する属性：名称、座標、収容台数（`capacity`）、種別（地上・立体・地下）、有料/無料（`fee`）など、存在するもの
- 地名検索には OpenStreetMap 系のジオコーディング API（Nominatim 等）を利用する

### 7.2 提供元の切り替えを考慮した設計
- 地図の描画と駐車場データの取得を、それぞれ共通インターフェースで抽象化する
- 画面側のコードは特定の提供元（Leaflet / Overpass / Google）に直接依存しない
- 提供元の切り替えは設定値（環境変数等）の変更だけで行える構造とする

### 7.3 データ保存
- お気に入り・メモ・設定値はブラウザの localStorage に保存する
- サーバー側にはユーザーデータを保存しない

## 8. 非機能要件

| 分類 | 要件 |
|---|---|
| コスト | 月額費用 0 円で運用できる（無料のホスティングと無料 API のみを使用） |
| 対応端末 | スマホ優先のレスポンシブデザイン（画面幅 360px 以上）。PC ブラウザでも利用できる |
| 対応ブラウザ | iOS Safari、Android Chrome、PC 版 Chrome の最新版 |
| 操作性 | 片手でも操作しやすいよう、主要ボタンは画面下部に配置し、タップ領域を十分に確保する |
| 性能 | 地点をタップしてから結果が表示されるまで、通常時 3 秒以内（モバイル回線）を目標とする |
| 可用性 | 外部 API の障害時もアプリ自体は落ちず、エラーを表示して再試行できる |
| API 利用規約 | Overpass / Nominatim / OSM タイルの利用ポリシー（リクエスト頻度・User-Agent・帰属表示）を守る |
| 負荷配慮 | 同じ条件の検索結果は一定時間キャッシュし、連続タップ時は処理を間引いて外部 API への過剰なリクエストを避ける |
| セキュリティ | 外部データの表示時に XSS 対策を行う。入力値をバリデーションする |
| 帰属表示 | 「© OpenStreetMap contributors」を地図上に表示する |
| インストール性 | PWA として、ホーム画面に追加できる |

## 9. 成功の定義

- 出発前・到着直前の両方のシーンで、目的地周辺の駐車場を **30 秒以内** に把握できる
- 生活圏内のよく行く目的地で、実際に利用できる駐車場が候補として表示される
- 月額費用 0 円で継続して運用できている

## 10. 制約・リスク

| リスク | 影響 | 対策 |
|---|---|---|
| OSM データの網羅性（小さいコインパーキングの抜け） | 候補が不足する | 実際に使って網羅性を評価し、不十分なら Google への切り替え（F-12）を検討する |
| 公開 Overpass API の応答遅延・利用制限 | 検索が遅くなる、失敗する | キャッシュと再試行、複数の Overpass エンドポイントの利用を検討する |
| 位置情報の取得に HTTPS が必須 | 現在地検索が使えない | HTTPS 対応の静的ホスティングを利用する |
