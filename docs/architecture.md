# 技術仕様書

本書は `docs/functional-design.md` の設計を実現するための技術スタック、開発ツール、技術的な制約を定義する。

## 1. テクノロジースタック

### 1.1 アプリケーション

| 分類 | 採用技術 | 採用理由 |
|---|---|---|
| 言語 | TypeScript（strict モード） | プロバイダのインターフェースを型で強制でき、提供元を切り替えるときの修正漏れを防げる |
| UI ライブラリ | React | コンポーネント設計（機能設計書 6 章）をそのまま実装できる。利用できる地図ライブラリが多い |
| ビルドツール | Vite | 設定が少なく、開発サーバーの起動と反映が速い。環境変数（`VITE_*`）で提供元を切り替えられる |
| スタイリング | Tailwind CSS | プロジェクト共通のデザインシステムとして採用（CLAUDE.md の方針） |
| 地図 | Leaflet ＋ react-leaflet | 無料・軽量で、OSM タイルを API キーなしで扱える |
| PWA | vite-plugin-pwa | マニフェストと Service Worker を自動生成できる |

### 1.2 外部サービス

| 用途 | サービス | 認証 | 費用 |
|---|---|---|---|
| 地図タイル | OpenStreetMap 標準タイル（`tile.openstreetmap.org`） | 不要 | 無料 |
| 駐車場データ | Overpass API（公開インスタンス） | 不要 | 無料 |
| 地名検索 | Nominatim（`nominatim.openstreetmap.org`） | 不要 | 無料 |
| ナビ | Google マップの URL スキーム | 不要 | 無料 |
| ホスティング | GitHub Pages（GitHub Actions でデプロイ） | GitHub アカウント | 無料 |

- ホスティングは HTTPS 必須（Geolocation API と Service Worker の要件）。GitHub Pages は標準で HTTPS に対応している
- 将来 Google に切り替える場合は、Maps JavaScript API・Places API の API キーが必要になる。その際は、キーの利用元を自サイトのドメインに限定する「HTTP リファラー制限」を必ず設定する

### 1.3 開発ツール

| 分類 | ツール | 用途 |
|---|---|---|
| ランタイム | Node.js 24 系（開発コンテナの既定） | ビルド・開発サーバー |
| パッケージ管理 | npm | 依存関係の管理。`package-lock.json` をコミットする |
| リンター | ESLint（typescript-eslint、react-hooks プラグイン） | 静的解析 |
| フォーマッター | Prettier（prettier-plugin-tailwindcss） | コード整形、Tailwind のクラス順の統一 |
| 型チェック | `tsc --noEmit` | 型の検査 |
| 単体テスト | Vitest ＋ Testing Library | サービス層・プロバイダ層・コンポーネントのテスト |
| API モック | MSW（Mock Service Worker） | Overpass・Nominatim の応答をテストで再現する |
| E2E テスト | Playwright | スマホ画面サイズでの主要操作の確認（開発コンテナに依存関係を導入済み） |
| CI/CD | GitHub Actions | プッシュ時のリント・型チェック・テストと、main ブランチへのマージ時のデプロイ |

### 1.4 バージョン方針

- 各ライブラリは導入時点の最新の安定版を使い、`package.json` と `package-lock.json` でバージョンを固定する
- メジャーバージョンの更新は、個別の作業（ステアリングディレクトリ）として実施する

## 2. アーキテクチャ上の技術判断

### 2.1 バックエンドを持たない

| 観点 | 判断 |
|---|---|
| 理由 | 月額 0 円の要件、個人利用で認証が不要、必要な API がすべてブラウザから直接呼び出せる |
| トレードオフ | API キーを隠せない。OSM 系はキー不要なので問題ない。Google に切り替える場合はリファラー制限で対応する |
| 見直す条件 | 複数端末での同期が必要になったとき、またはキーを完全に秘匿する必要が出たとき |

### 2.2 提供元の選択方法

- ビルド時の環境変数で選ぶ（例：`VITE_PROVIDER=osm`）。既定値は `osm`
- 選ばれなかった提供元のコードは、動的 import でバンドルから切り離す。これにより、OSM 構成のアプリに Google 用のコードが含まれないようにする

### 2.3 状態管理

- React 標準の `useState`・`useReducer`・カスタムフックで管理する
- 画面が単一で、状態の種類も少ない（機能設計書 6.1 節）ため、外部の状態管理ライブラリは導入しない

## 3. 技術的制約

### 3.1 外部 API の利用ポリシー

| サービス | 主な制約 | 対応 |
|---|---|---|
| OSM タイル | 大量取得の禁止、帰属表示が必須 | 通常の地図操作の範囲で使う。Service Worker でタイルを大量に先読みしない。地図上に帰属表示を出す |
| Overpass API | 公開インスタンスは負荷が高いとリクエストを拒否する（HTTP 429 / 504） | キャッシュ、1 秒以上の呼び出し間隔、タイムアウト 15 秒、失敗時の再試行ボタン（機能設計書 4.1 節） |
| Nominatim | 最大 1 リクエスト / 秒、自動補完での利用禁止、アプリの識別が必要 | ボタンを押したときだけ検索する。ブラウザが送る Referer ヘッダーでアプリを識別させる |

- Overpass のエンドポイントは設定値として持ち、応答が悪いときに別の公開インスタンスへ切り替えられるようにする

### 3.2 ブラウザの制約

| 制約 | 内容 | 対応 |
|---|---|---|
| 位置情報 | HTTPS でのみ使える。iOS では利用者の許可が毎回必要になる場合がある | 拒否時・失敗時の案内を表示する |
| localStorage | 容量は約 5MB。iOS Safari では長期間使わないとデータが消える場合がある | お気に入り・設定の用途なら容量は十分。消失リスクは個人利用として許容する |
| ボトムシートの操作 | スマホではスクロール操作と地図のドラッグ操作がぶつかりやすい | シート内のスクロール中は地図の操作を無効にする |

## 4. パフォーマンス要件

| 項目 | 目標値 | 手段 |
|---|---|---|
| 初回表示（モバイル回線） | 3 秒以内に地図が操作可能になる | Vite による分割バンドル、不要な提供元コードの除外 |
| JavaScript のバンドルサイズ | 初回読み込み分を gzip 圧縮後 200KB 以下 | 依存ライブラリを最小限にする。ビルド時にサイズを確認する |
| 地点タップから結果表示まで | 通常時 3 秒以内 | Overpass の `around` 検索で必要な範囲だけ取得する。キャッシュを使う |
| マーカーの描画 | 1km 範囲で 100 件程度の結果でも操作がもたつかない | 通常のマーカー描画で対応する。不足する場合はマーカーのクラスタリングを検討する |
| 2 回目以降の起動 | アプリ本体はオフラインでも起動する | Service Worker でアプリ本体（HTML・JS・CSS）をキャッシュする |

## 5. セキュリティ

| 項目 | 対策 |
|---|---|
| XSS | 外部データ（駐車場名・運営者・メモ）は React のテキストとして描画する。`dangerouslySetInnerHTML` と、Leaflet のポップアップへの HTML 文字列の直接埋め込みは使わない |
| 入力値の検証 | 地名検索の文字列は前後の空白を除去し、長さを上限 100 文字に制限する。メモは 500 文字まで |
| 外部 URL | ナビ用 URL に埋め込む座標は数値として検証する。外部リンクには `rel="noopener noreferrer"` を付ける |
| 外部 API の応答 | 応答を型ガードで検証し、想定外の形式のデータは破棄する |
| Content Security Policy | 通信先を自サイトと利用する外部サービス（OSM タイル・Overpass・Nominatim）に限定する。GitHub Pages ではレスポンスヘッダーを設定できないため、`<meta http-equiv="Content-Security-Policy">` で指定する |
| 秘密情報 | OSM 構成では API キーを持たない。将来の Google 構成でも、キーはリファラー制限付きの公開前提キーだけを使う |
