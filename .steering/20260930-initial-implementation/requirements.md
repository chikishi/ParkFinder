# 要求内容：初回実装

## 1. 作業の概要

`docs/` で定義したプロダクトの最初のバージョンを実装する。
開発環境の構築から、スマホで実際に使える状態で GitHub Pages に公開するまでを対象とする。

## 2. 対象範囲

### 2.1 実装する機能

`docs/product-requirements.md` 4 章の **P0（必須）と P1（初回リリースに入れたい）** をすべて実装する。

| ID | 機能 | 優先度 |
|---|---|---|
| F-01 | 地図表示 | P0 |
| F-02 | 地点指定検索 | P0 |
| F-03 | 検索結果の地図表示 | P0 |
| F-04 | 検索結果の一覧表示 | P0 |
| F-05 | 検索半径の指定 | P0 |
| F-06 | 現在地検索 | P0 |
| F-07 | ナビ連携 | P0 |
| F-08 | 駐車場詳細表示 | P0 |
| F-09 | 地名・住所検索 | P1 |
| F-10 | お気に入り・メモ | P1 |

### 2.2 あわせて整備するもの

| 項目 | 内容 |

## 3. ユーザーストーリー

`docs/product-requirements.md` 5 章の US-01〜US-07 をすべて対象とする。

## 4. 受け入れ条件

### 4.1 機能

- `docs/product-requirements.md` 6 章の受け入れ条件をすべて満たす
- `docs/functional-design.md` 4.5 節のエラー処理（検索失敗、0 件、位置情報の拒否、地名検索 0 件、オフライン）が表示される

### 4.2 品質

- `npm run check`（リント・型チェック・単体テスト）がすべて成功する
- `npm run test:e2e` で、次のシナリオがスマホの画面サイズで成功する
  1. 地図をタップすると、周辺の駐車場が地図と一覧に表示される
  2. 検索半径を変更すると再検索される
  3. 一覧から駐車場を選ぶと詳細が表示され、ナビのリンクに正しい座標が入っている
  4. 現在地ボタンで、現在地の周辺が検索される
  5. 地名検索で候補を選ぶと、その地点の周辺が検索される
  6. お気に入りとメモが、ページを再読み込みしても残っている
- ロジック部分（`utils/`、`services/`、`storage/`、`providers/osm/` の地図コンポーネント以外）の行カバレッジが 80% 以上
- `src/` の中で、Leaflet を import しているのは `providers/osm/` だけである（ESLint で検査されている）
- 初回に読み込む JavaScript が gzip 圧縮後 200KB 以下

### 4.3 公開・実機での確認

- GitHub Pages に HTTPS で公開されている
- 開発者本人のスマホで次のことを確認できる
  - ホーム画面に追加して起動できる
  - 現在地検索が動作する
  - 生活圏内のよく行く目的地で、周辺の駐車場が表示される

## 5. 制約事項

- **月額 0 円**で運用できる構成とする。有料のサービスや API キーを使わない
- 外部 API（OSM タイル、Overpass、Nominatim）の利用ポリシーを守る（`docs/architecture.md` 3.1 節）
- 自動テストから実際の外部 API を呼び出さない（MSW でモックする）
- GitHub Pages への公開には、公開用の GitHub リポジトリの作成と Pages の設定が必要になる。これは開発者本人が行う（手順は README に記載する）
- 開発は `docs/development-guidelines.md` の規約に従う

## 6. 実機確認後の判断事項

公開後、実際に使ってみて次の点を評価し、次の作業を決める。

- OSM データの網羅性：よく行く目的地の周辺で、実在する駐車場がどの程度表示されるか。不足が大きければ、Google への切り替え（F-12）を次の作業にする
- 公開 Overpass API の応答速度：3 秒以内の目標を満たせているか
